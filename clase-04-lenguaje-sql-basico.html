¿Cómo llevamos el esquema del papel a una base real?

Ya tenemos un diagrama entidad-relación y un esquema relacional normalizado. Pero un dibujo no guarda datos, no rechaza errores y no responde preguntas. Para eso necesitamos un lenguaje que el sistema gestor de bases de datos (SGBD) entienda: SQL.

→
Unidad 3Esquema relacionalTablas, llaves y normalización
→
HoyScript SQLCREATE TABLE, INSERT, SELECT
→
ResultadoBase de datos realCon datos y reglas que se cumplen

Analogía de Mixtle: el edificio. El diagrama es el plano. Con DDL levantas la construcción: muros, pisos y reglamento. Con DML la habitas: metes muebles, los cambias de lugar o los sacas. Con SELECT preguntas qué hay en cada cuarto sin mover nada. Si cambias el plano de un edificio ya habitado, es una obra; si cambias un mueble, es una mudanza. Por eso el SQL se divide en grupos.

Los tres grupos de sentencias de hoy

DDL

Define la estructura. Crea, modifica o elimina tablas y reglas.

CREATE · ALTER · DROP

DML

Manipula los datos. Agrega, cambia o borra filas.

INSERT · UPDATE · DELETE

SELECT

Consulta. Lee datos sin modificarlos.

SELECT … FROM … WHERE

4.1
Lenguaje de definición de datos

DDL: CREATE, ALTER y DROP

El DDL trabaja sobre la estructura. Cada tabla de tu esquema relacional se convierte en una sentencia CREATE TABLE: ahí decides el nombre de las columnas, su tipo de dato y las reglas que deben cumplir.

CREATE

Construye una tabla nueva.

SQL
CREATE TABLE categoria (
  id_categoria INTEGER PRIMARY KEY,
  nombre VARCHAR(40) NOT NULL
);

ALTER

Cambia una tabla que ya existe, por ejemplo agrega una columna.

SQL
ALTER TABLE categoria
  ADD COLUMN descripcion VARCHAR(100);

DROP

Elimina la tabla completa, con todos sus datos.

SQL
DROP TABLE categoria;
-- Sin pregunta de confirmación.
Cuidado con DROP: borra la estructura y todos los datos a la vez. En SQL no hay botón de "deshacer" automático. Por eso, antes de ejecutarlo, verifica el nombre de la tabla.

Tipos de datos más usados

TipoPara qué sirveEjemplo
INTEGERNúmeros enteros: identificadores, cantidades, existencias.id_producto = 12
VARCHAR(n)Texto de hasta n caracteres: nombres, correos.'Mochila'
DECIMAL(p,s)Números con decimales exactos, ideal para dinero. p = dígitos totales, s = decimales.DECIMAL(8,2) → 1234.50
DATEFechas en formato año-mes-día.'2026-10-24'

4.2
Lenguaje de manipulación de datos
DML: INSERT, UPDATE y DELETE


    
Con la estructura lista, el DML trabaja sobre las filas: agrega registros nuevos, modifica los existentes o elimina los que ya no se necesitan.


    

      
INSERT
Agrega filas. Escribe siempre la lista de columnas.

        
SQL
INSERT INTO categoria
  (id_categoria, nombre)
VALUES
  (1, 'Papelería'),
  (2, 'Cómputo');

      
UPDATE
Cambia valores de filas existentes.

        
SQL
UPDATE producto
SET precio = 50.00
WHERE id_producto = 1;

      
DELETE
Elimina filas que cumplen una condición.

        
SQL
DELETE FROM pedido
WHERE id_pedido = 4;

    


    

      Regla de oro del DML
      
UPDATE y DELETE sin WHERE afectan a todas las filas de la tabla.

    


    

      
      

        
Piénsalo así: WHERE es el cinturón de seguridad. Sin él puedes reducir el precio de todos los productos a cero o vaciar la tabla de clientes con una sola línea. Antes de ejecutar un UPDATE o DELETE, pregúntate: ¿qué filas va a tocar?

4.3
Consultas simples
SELECT: hacer preguntas a la base de datos


    
Un SELECT no cambia nada: solo lee. Se arma por cláusulas, y cada una responde una pregunta distinta.

    
SQL
SELECT   nombre, precio        -- ¿QUÉ columnas quiero ver?
FROM     producto              -- ¿DE QUÉ tabla?
WHERE    precio > 100          -- ¿QUÉ filas cumplen la condición?
ORDER BY precio DESC           -- ¿EN QUÉ orden?
LIMIT    3;                    -- ¿CUÁNTAS filas como máximo?


    

      

        
OperadorUsoEjemplo

        
          
= <> > < >= <=Comparar valoresWHERE existencia = 0

          
AND · ORCombinar condicionesWHERE id_categoria = 2 AND precio < 200

          
LIKETexto con comodín: % = cualquier cantidad de caracteresWHERE nombre LIKE 'M%'

          
BETWEENRango, incluyendo los extremosWHERE precio BETWEEN 100 AND 300

        
      

    


    
Detalle de motor: en SQLite, LIKE no distingue mayúsculas de minúsculas para letras sin acento; en PostgreSQL sí las distingue. Por eso conviene escribir el patrón tal como está guardado el dato.

4.4
Integridad de los datos
Restricciones y llaves


    
Las restricciones son reglas que la propia base de datos hace cumplir. No dependen de que el usuario se acuerde: si alguien intenta guardar un dato que las viola, el sistema lo rechaza.


    

      

        
RestricciónGarantiza que…Ejemplo

        
          
PRIMARY KEYCada fila se identifica de forma única y nunca es nula.id_producto

          
FOREIGN KEYEl valor existe en la tabla a la que apunta.pedido.id_cliente → cliente

          
NOT NULLLa columna siempre tiene valor.nombre

          
UNIQUENo se repiten valores.correo

          
CHECKEl valor cumple una condición.precio > 0

          
DEFAULTSi no se indica valor, se usa uno por omisión.existencia = 0

Proyecto integrador
Las bases técnicas de tu proyecto


    
El proyecto integrador que vienen trabajando necesita una base de datos. Hoy dejan sus cimientos: al menos un diagrama con las entidades principales y sus relaciones, y un primer script que lo convierte en tablas. Lo que construyas aquí será el punto de partida del producto de la unidad: el script SQL ejecutable.


    
Paso 1 · Descubre las entidades en la descripción del proyecto

    
Lee tu proyecto como una historia. Cada tipo de palabra te sirve para una parte del diseño:

    

      
Un cliente (nombre, correo) realiza varios pedidos (fecha), y cada pedido incluye uno o más productos (nombre, precio).

      
Sustantivo = candidato a entidad (tabla)Verbo = relación entre entidadesDato = atributo (columna)

    


    

      
1 · ¿Qué cosas debo recordar?
Personas, objetos y eventos que el sistema tiene que guardar. Cada una es una entidad.

      
2 · ¿Qué datos tiene cada cosa?
Cada entidad necesita una llave primaria y los datos que describen a cada registro.

      
3 · ¿Cómo se relacionan?
Lee cada relación en sus dos sentidos: ¿cuántos de un lado por cada uno del otro? Y al revés.

Captura tus entidades, atributos y relaciones. El lienzo dibuja el diagrama y genera el script SQL con las llaves foráneas colocadas según la cardinalidad. Cárgalo con el ejemplo para ver cómo funciona y luego pulsa Nuevo proyecto.

    Script SQL (DDL) ejecutable que implementa físicamente la estructura de la base de datos diseñada, con sus restricciones de integridad, junto con sentencias DML y consultas SELECT sobre las tablas creadas. Equivale al 20% de la calificación final.
    
      
      
        
    • Todas las tablas del diseño, con llave primaria y llaves foráneas colocadas según la cardinalidad.
      • 
        
    • Restricciones de integridad: NOT NULL, UNIQUE, CHECK o DEFAULT donde correspondan.
      • 
        
    • Al menos algunos registros de prueba con INSERT y consultas SELECT con condiciones.
      • 
        
    • El script se ejecuta completo, de principio a fin, sin errores.

    Conclusión
    
    
    SQL permite pasar de un diseño en papel a una base de datos que funciona y que se defiende sola. El DDL construye la estructura, el DML mantiene vivos los datos y el SELECT los consulta, mientras las restricciones y las llaves foráneas hacen cumplir las reglas del negocio. Las llaves foráneas no son un detalle técnico: son la cardinalidad que ya sabes leer, escrita en el lenguaje del sistema gestor. Con el diagrama y el primer script de hoy, tu equipo tiene los cimientos del proyecto integrador sobre los cuales seguir construyendo.
